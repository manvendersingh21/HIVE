### Added

- Assignments gained an `execution` field (`"direct"`, the default, or `"scheduler"`). Heavy work (`gpu-compute`/`heavy-compute`) on a slurm-tagged device is now accepted when `execution = "scheduler"`, and Hive appends a mandatory sbatch/srun + squeue instruction block to such an assignment's objective after validation, so the planner cannot drop the scheduler rules. Scheduler execution on a device without the slurm tag is rejected.
- The machine inventory probe now records scheduler health for slurm-tagged devices by parsing `sinfo` node states (`scheduler_health`: usable while any node is schedulable, unusable when every reported node is DRAIN/DOWN/INVALID). Health is shown to the planner in the fleet listing, and a scheduler-execution assignment on a device whose scheduler is unusable is rejected with the operator's way out.
- Per-device `allow_direct_gpu = true` override in `config/workers.toml` permitting direct `gpu-compute`/`heavy-compute` work on a slurm/login-node/light-tagged device when its scheduler is broken; `config/workers.example.toml` documents it and carries a commented-out example for `cis-a6000` (DRAIN+INVALID_REG, "gres/gpu count reported lower than configured"), never enabled by default.
