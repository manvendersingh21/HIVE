### Security
- Peer commands can no longer impersonate another run. Each runner process issues a fresh per-run credential and passes it only through the native agent's environment (`HIVE_RUN_CREDENTIAL`). The journal stores only its SHA-256 hash, and the credential never appears in prompts, journal events, snapshots or runner output; if an agent echoes it, it is redacted. `runner.py peer` refuses, writing nothing, unless the credential matches the target journal's stored hash. Auto-approval (runner policy, AGY hook and the web re-assessment, which now passes `--run-id`) accepts a peer command only when its `--run-id` is the calling run. Native `hive peer` tools are unchanged.
